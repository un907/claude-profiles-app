# Claude Profiles

[English](README.md)

Claude Profilesは、Claude Desktopの複数のログイン環境を並べて起動するmacOSのメニューバー用ランチャーです。Claude Desktop本体は改変しません。追加したプロフィールごとに専用のElectron `--user-data-dir`と`CLAUDE_CONFIG_DIR`を割り当てて別プロセスとして起動するため、ログイン状態は分離したまま、Claude Codeの設定は共有できます。

> 非公式のツールです。Anthropicによる提供・承認・サポートを受けたものではありません。

## できること

- 標準プロフィールと追加したプロフィールを1つの一覧に表示します
- 停止中のプロフィールは起動し、起動中のプロフィールは前面に表示します
- 起動処理中はすぐに表示が切り替わり、同じプロフィールの二重起動を防ぎます
- 残りのプロフィールをまとめて起動できます
- 画面からプロフィールの追加、名前と識別色の変更ができます
- 起動中のプロフィールを個別に終了・再起動できます
- 使わないプロフィールは、データを消さずにアーカイブして後から復元できます
- 各プロフィールの最終利用時刻を表示します
- 起動後にランチャーのウィンドウを自動で閉じる設定があります
- Claude Desktopの検出状態と登録数を簡易診断します
- メニューバーに常駐し、ランチャー自身の多重起動を防ぎます
- Claude CodeのAgents・Rules・Skills・Hooks・権限設定・Plugins・Auto Memoryを全プロフィールで共有します
- プロフィールごとのコマンドで、ターミナルからそのプロフィールの設定でClaude Codeを起動できます（「ターミナルから使う」の節を参照）
- アプリ自身を自動で更新します（「自動更新」の節を参照）

## 必要な環境

- macOS 13以降
- `/Applications/Claude.app`にインストール済みのClaude Desktop
- XcodeまたはSwift 5.10以降（ソースからビルドする場合のみ）

## インストール

1. [最新のリリース](https://github.com/un907/claude-profiles-app/releases/latest)から`Claude.Profiles-<バージョン>.dmg`をダウンロードします。
2. DMGを開き、**Claude Profiles**を**Applications**フォルダへドラッグします。
3. **初回起動の前に、必ずApplicationsフォルダへ移動してから起動してください。** DMGの中やダウンロードフォルダから直接起動すると、macOSがアプリを読み取り専用の一時的な場所で動かす仕組み（App Translocation）が働き、アップデートをインストールできなくなります。
4. DMGを取り出し、ApplicationsフォルダからClaude Profilesを起動します。

### 初回起動とGatekeeper

このアプリはアドホック署名で、Appleの公証を受けていません。そのため初回起動時は「"Claude Profiles"は開発元を確認できないため開けません」などのメッセージが表示されて起動が止まります。文言はmacOSのバージョンによって異なります。次のどちらかの方法で一度だけ許可してください。

- FinderでApplicationsフォルダの**Claude Profiles**を右クリック（またはControlキーを押しながらクリック）し、**開く**を選んでから、確認画面でもう一度**開く**を押します。
- **システム設定 → プライバシーとセキュリティ**を開き、Claude Profilesについての表示までスクロールして**このまま開く**を押します。バージョンによってボタンの名前が異なる場合があります。その後、もう一度アプリを起動します。

許可が必要なのは初回の1回だけです。以後の自動更新では、更新機能がダウンロードしたアプリの隔離属性を自分で外すため、追加の操作なしで起動できます。

## 自動更新

Claude Profilesは[Sparkle](https://sparkle-project.org/)で自動更新します。新しいバージョンの有無を1日1回確認し、インストールの前に確認画面を出します。メニューバーのメニューにある**アップデートを確認…**から、いつでも手動で確認できます。更新ファイルはこのリポジトリのGitHub Releasesから取得し、インストール前にEdDSA署名を検証します。

## ターミナルから使う

追加したプロフィールごとに、ターミナル用のコマンドを設定できます。**名前・用途・色を編集**の**CLIコマンド**欄で、固定の`claude-`に続く名前を入力します。たとえば`review`と入力して保存すると、ターミナルで`claude-review`と打つだけで、そのプロフィールの`CLAUDE_CONFIG_DIR`、つまりそのプロフィールのログインでClaude Codeが起動します。標準プロフィールにはコマンドがなく、普通の`claude`がその役割を持ちます。

- コマンドの実体は、アプリが`~/.local/bin/claude-<名前>`に書き出す小さなシェルスクリプトです。`CLAUDE_CONFIG_DIR`を設定してから`claude`を実行します。
- アプリはこのスクリプトを常に設定と一致させます。プロフィール名やコマンド名を変えると書き直し、コマンド名を空にした時やアーカイブした時は削除します。アプリの起動時にも毎回照合します。
- 生成したスクリプトには`# Generated by Claude Profiles`という行が入っています。この行がないファイルは、上書きも削除もしません。同じ名前の自分のファイルが既にある場合は、エラーを表示して作成しません。
- `~/.local/bin`がシェルの`PATH`に含まれている必要があります。含まれていない場合は編集画面に注意書きが出ます。たとえば`~/.zshrc`に`export PATH="$HOME/.local/bin:$PATH"`を追加してください。
- スクリプトは標準では`PATH`上の`claude`を実行します。特定の実行ファイルやラッパーを使う場合は、設定のターミナル欄にある**CLIが呼び出すclaude**に指定します。値を変えると全スクリプトを書き直します。

### 巻き戻し用スナップショットと入力履歴の統合

`file-history`と`history.jsonl`は、置き換えるのではなく標準プロフィールへ統合してから接続します。追加プロフィールの`file-history`にあるセッションごとのフォルダは、標準プロフィールの`file-history`へ移します。同じセッションIDのフォルダが既にある場合は標準プロフィール側を残し、追加プロフィール側は`Migration Backups/<プロフィールID>/Shared History/`へ退避します。`history.jsonl`は両方の行を合わせ、完全に同じ行を取り除いてから`timestamp`の順に並べます。`timestamp`のない行やJSONとして読めない行は捨てずに、元の順序のまま末尾に残します。標準プロフィール側のファイルは1回の操作でまとめて置き換え、元の2つのファイルは同じ退避フォルダに残します。統合に失敗した場合は、そのプロフィールを起動せずにエラーを表示します。

### 起動中のセッションを別のプロフィールへ移す

`extras/claude-commands/switch.md`は、今のセッションを別のプロフィールへ移すためのClaude Codeのコマンドです。`~/.claude/commands/`にコピーして使います。アプリは自動では配置しません。セッションの中で`/switch review`と入力すると、`claude-review`が`PATH`にあることを確かめてから`claude-review --resume <セッションID>`を表示し、クリップボードにコピーします。セッションを終了してから貼り付けて実行すると、同じ会話をそのプロフィールで続けられます。`/switch main`（または`/switch claude`）は標準プロフィールへ戻る用で、`claude --resume <セッションID>`を表示します。`/switch`だけを入力すると、使える`claude-*`コマンドの一覧を表示します。

## 仕組み

追加プロフィールごとに専用のElectron `user-data-dir`と`CLAUDE_CONFIG_DIR`を割り当て、Claude Desktopを別プロセスとして起動します。ログイン、Cookie、Claude Desktopの会話一覧、アカウントの状態はプロフィールごとに分離したままです。各プロフィールのClaude Codeの設定のうち、ユーザー指示（`CLAUDE.md`）、Agents、Rules、Hooks、Commands、Skills、Output Styles、Settings、Pluginsは標準プロフィールへ接続します。`projects`も標準プロフィールへ接続するため、Auto MemoryとClaude Codeのプロジェクト保存データは共通になります。Claude Codeの巻き戻し用スナップショット（`file-history`）と入力履歴（`history.jsonl`）も共有するため、別のプロフィールで再開したセッションでも巻き戻しと入力履歴を使えます。`CLAUDE_CONFIG_DIR`の外、ホームフォルダ以下にデータを置くツールは、同じデータをそのまま使います。標準プロフィールは、これらの起動引数を持たないClaudeプロセスとして区別します。Claude Desktop本体と`app.asar`は変更しません。

## データと安全性

- プロフィール一覧は`~/Library/Application Support/Claude Profiles Launcher/profiles.json`に保存します。
- 新しいプロフィールのデータも同じフォルダ以下に作成します。
- 認証情報はClaude自身の保存領域で保持します。MCP設定を同期する時は他の項目も含む設定ファイルを読み込みますが、認証に関わる項目のコピーやログ出力は行いません。
- 認証データをコピー・移動・削除する機能はありません。
- アーカイブは一覧から隠すだけで、ログインのデータは削除しません。
- 1つのプロフィールの保存領域を2つのClaudeプロセスが同時に使わないよう、起動中のプロセスを監視します。
- 初めて共有する時は既存の履歴に競合がないかを事前に検査し、追加プロフィール側の元のデータを`Migration Backups`に残してから統合します。
- 設定を共有する前に追加プロフィール側の既存の設定を`Migration Backups`に残し、途中で失敗した場合は元の状態に戻します。
- `.claude.json`の全体は共有しません。起動の準備で、MCPの接続定義と有効化の設定だけを標準プロフィールから同期します。プロジェクトごとの接続定義も対象です。ログイン、信頼の確認、使用履歴はプロフィールごとに保持します。
- 指示から参照されることの多い補助ファイルとフォルダの決まった一覧も共有します。`scripts`、`docs`、`templates`、`AGENTS.md`、`launch.json`などが含まれ、全体は`Sources/ClaudeProfilesCore/SharedConfigurationParityStore.swift`に記載しています。
- 独自のファイルやフォルダも共有したい場合は、`~/Library/Application Support/Claude Profiles Launcher/extra-shared-items.txt`に1行1項目で名前を書きます。`#`で始まる行と空行は無視します。`/`や`..`を含む名前と`.`は設定フォルダの外を指すため無視し、システムログに警告を残します。ファイルはプロフィールの起動準備のたびに読み直すため、再起動は不要です。一覧から名前を消しても、作成済みのリンクは削除しません。`projects`、`file-history`、`history.jsonl`は統合付きで共有する組み込みの項目のため、指定しても無視します。
- `remote-settings.json`、セッション、テレメトリ、組織のキャッシュは共有しません。起動済みのセッションは古い設定を保持している場合があるため、MCPの設定を変えた後は新しいセッションで接続を確認してください。
- Claude Desktopの会話一覧はプロフィールごとに独立したままです。共有されるのは、会話から抽出されたメモリとClaude Codeの保存データです。
- 同じClaude Codeのセッションを複数のプロフィールで同時に再開すると、履歴が混ざる可能性があります。1つのセッションは一度に1つのプロフィールで利用してください。

## ソースからのビルド

```bash
swift test
Scripts/build-app.sh 1.0.0
```

`dist/Claude Profiles.app`と`dist/Claude.Profiles-1.0.0.zip`が作成されます。`Scripts/make-dmg.sh 1.0.0`を実行するとDMGも作成されます。リリースの手順は[`docs/RELEASING.md`](docs/RELEASING.md)、UI/UXの設計方針は[`docs/DESIGN.md`](docs/DESIGN.md)にあります。
