# Claude Profiles

[日本語](README.ja.md)

Claude Profiles is a small macOS menu-bar launcher that runs several Claude Desktop logins side by side. It does not modify Claude Desktop. Each extra profile is started as a separate Claude Desktop process with its own Electron `--user-data-dir` and its own `CLAUDE_CONFIG_DIR`, so sign-in state stays separate while your Claude Code configuration is shared.

> This is an unofficial tool. It is not provided, endorsed, or supported by Anthropic.

## Features

- Shows the default profile and any additional profiles in one list
- Starts a stopped profile, or brings an already running one to the front
- Prevents the same profile from being started twice, with immediate launch feedback
- Starts all remaining profiles at once
- Adds, renames, and recolors profiles from the app
- Quits or restarts a running profile individually
- Archives unused profiles without deleting any data, and restores them later
- Shows when each profile was last used
- Optionally closes the launcher window after a launch
- Shows a quick diagnosis of the Claude Desktop installation and the profile count
- Lives in the menu bar and prevents multiple copies of itself from running
- Shares Claude Code agents, rules, skills, hooks, permissions, plugins, and Auto Memory across profiles
- Starts Claude Code in a terminal with a profile's settings through a per-profile command (see [Using profiles from the terminal](#using-profiles-from-the-terminal))
- Updates itself (see [Automatic updates](#automatic-updates))

## Requirements

- macOS 13 or later
- Claude Desktop installed at `/Applications/Claude.app`
- Xcode or Swift 5.10 or later (only to build from source)

## Installation

1. Download `Claude.Profiles-<version>.dmg` from the [latest release](https://github.com/un907/claude-profiles-app/releases/latest).
2. Open the DMG and drag **Claude Profiles** onto the **Applications** folder.
3. **Always move the app to Applications before the first launch.** If you start it directly from the DMG or from Downloads, macOS runs it from a randomized read-only location (App Translocation) and the updater refuses to install updates.
4. Eject the DMG and start Claude Profiles from Applications.

### First launch and Gatekeeper

The app is ad-hoc signed and not notarized by Apple, so the first launch is blocked with a message such as *"Claude Profiles" cannot be opened because the developer cannot be verified* (the exact wording differs between macOS versions). To allow it once:

- In Finder, right-click (or Control-click) **Claude Profiles** in Applications, choose **Open**, then confirm **Open**; or
- Open **System Settings → Privacy & Security**, scroll to the message about Claude Profiles, and click **Open Anyway** (on some versions the button is labeled differently). Then launch the app again.

You only need to approve the app once. Later updates installed by the built-in updater remove the quarantine flag themselves, so they launch without another prompt.

## Automatic updates

Claude Profiles uses [Sparkle](https://sparkle-project.org/). It checks for a new version once a day and asks before installing anything. You can also check at any time from the menu-bar menu (**アップデートを確認…**, "Check for Updates…"). Updates are downloaded from this repository's GitHub Releases and verified with an EdDSA signature before installation.

## Using profiles from the terminal

Each additional profile can have a terminal command. In **Edit name, purpose and color** (名前・用途・色を編集), enter a name in the **CLIコマンド** (CLI command) field after the fixed `claude-` prefix, for example `review`. After saving, typing `claude-review` in a terminal starts Claude Code with that profile's `CLAUDE_CONFIG_DIR`, so it uses that profile's sign-in. The default profile has no command; plain `claude` already uses it.

- The command is a small shell script that the app writes to `~/.local/bin/claude-<name>`. It sets `CLAUDE_CONFIG_DIR` and then runs `claude`.
- The app keeps these scripts in sync: it rewrites them when a profile is renamed or the command name changes, and deletes them when the name is cleared or the profile is archived. It also checks them every time it starts.
- Every generated script contains the line `# Generated by Claude Profiles`. Files without that line are never overwritten or deleted. If one of your own files already uses the same name, the app shows an error instead.
- `~/.local/bin` must be on your shell's `PATH`. If it is not, the editor shows a note. Add `export PATH="$HOME/.local/bin:$PATH"` to `~/.zshrc`, for example.
- By default the scripts run the `claude` found on `PATH`. To use a specific executable or wrapper, set **CLIが呼び出すclaude** in the **ターミナル** (Terminal) section of Settings. All scripts are rewritten when this value changes.

### Merging rewind snapshots and prompt history

`file-history` and `history.jsonl` are merged into the default profile before they are linked, instead of being replaced. Each session folder in the profile's `file-history` is moved into the default profile's `file-history`; if a folder with the same session ID already exists there, the default profile's copy is kept and the profile's copy is saved to `Migration Backups/<profile ID>/Shared History/`. For `history.jsonl`, the lines of both files are combined, exact duplicates are removed, and the lines are sorted by their `timestamp` (lines without one, including lines that are not valid JSON, are kept at the end in their original order). The default profile's file is replaced in one atomic step, and both original files are kept in the same backup folder. If merging fails, the profile is not started and an error is shown.

### Switching a running session to another profile

`extras/claude-commands/switch.md` is a Claude Code command for moving the current session to another profile. Copy it to `~/.claude/commands/` (the app does not install it). In a session, `/switch review` checks that `claude-review` is on `PATH`, prints `claude-review --resume <session ID>`, and copies it to the clipboard. Exit the session and paste the command to continue the same conversation under that profile. `/switch main` (or `/switch claude`) does the same for the default profile, printing `claude --resume <session ID>`. `/switch` without a name lists the available `claude-*` commands.

## How it works

Every additional profile gets a dedicated Electron `user-data-dir` and `CLAUDE_CONFIG_DIR`, and Claude Desktop is launched as a separate process with them. Sign-in, cookies, the Claude Desktop conversation list, and account state stay separate per profile. The following Claude Code configuration in each profile is linked to the default profile: user instructions (`CLAUDE.md`), agents, rules, hooks, commands, skills, output styles, settings, and plugins. The `projects` directory is linked as well, so Auto Memory and Claude Code's saved project data are shared. Claude Code's rewind snapshots (`file-history`) and prompt history (`history.jsonl`) are shared too, so a session resumed under another profile can still be rewound and keeps its input history. Tools that keep their data in your home directory outside `CLAUDE_CONFIG_DIR` keep using that same data. The default profile is recognized as the Claude process started without these launch arguments. Claude Desktop itself and its `app.asar` are never modified.

## Data and safety

- The profile list is stored in `~/Library/Application Support/Claude Profiles Launcher/profiles.json`.
- Data for new profiles is created under the same folder.
- Credentials stay in Claude's own storage. When MCP settings are synchronized, the app reads configuration files that also contain other fields, but it never copies or logs authentication fields.
- The app has no feature that copies, moves, or deletes authentication data.
- Archiving only hides a profile from the list; it does not delete its sign-in data.
- Running processes are monitored so that one profile's storage is never used by two Claude processes at once.
- Before sharing for the first time, existing history is checked for conflicts, and the additional profile's original data is kept in `Migration Backups` before it is merged.
- Before settings are shared, the additional profile's existing settings are saved to `Migration Backups`; if something fails midway, the original state is restored.
- `.claude.json` is not shared as a whole. When a profile is prepared for launch, only MCP server definitions and their enabled state (including per-project definitions) are synchronized from the default profile. Sign-in, trust decisions, and usage history remain per profile.
- A fixed set of helper files and folders that instructions commonly refer to (for example `scripts`, `docs`, `templates`, `AGENTS.md`, and `launch.json`) is shared too. The full list is in `Sources/ClaudeProfilesCore/SharedConfigurationParityStore.swift`.
- To share additional files or folders of your own, list their names, one per line, in `~/Library/Application Support/Claude Profiles Launcher/extra-shared-items.txt`. Lines starting with `#` and empty lines are ignored. Names containing `/` or `..` (and `.` itself) are ignored with a warning in the system log, because they would point outside the configuration folder. The file is read every time a profile is prepared, so no restart is needed. Removing a name from the list does not delete links that were already created. `projects`, `file-history` and `history.jsonl` are ignored if listed, because they are already shared with a merge step.
- `remote-settings.json`, sessions, telemetry, and organization caches are not shared. Sessions that are already running may keep their old settings, so after changing MCP settings, check the connection in a new session.
- The Claude Desktop conversation list stays separate per profile. What is shared is the memory extracted from conversations and Claude Code's saved data.
- Resuming the same Claude Code session from several profiles at the same time can mix its history. Use one session from one profile at a time.

## Building from source

```bash
swift test
Scripts/build-app.sh 1.0.0
```

This produces `dist/Claude Profiles.app` and `dist/Claude.Profiles-1.0.0.zip`. `Scripts/make-dmg.sh 1.0.0` additionally creates the DMG. Release steps are described in [`docs/RELEASING.md`](docs/RELEASING.md), and the UI/UX design notes in [`docs/DESIGN.md`](docs/DESIGN.md).
